# design

请按照以下设计系统生成 UI 界面。

# 高级智能产品设计系统（Premium Intelligent Product Design System）

整体设计语言：

融合「环境式极简未来主义（Ambient Minimal Futuristic）」「柔和玻璃拟态（Soft Glassmorphism）」「平静科技（Calm Technology）」「精密仪器美学（Precision Instrument Aesthetic）」「极简动态界面语言（Minimal Motion Interface）」。

整体视觉方向：

打造一种高级、智能、可信赖、平静、精密、优雅的数字产品体验。界面应体现未来科技与人性化设计的结合，具有轻盈的空间感、柔和的视觉层次和专业的交互体验。

设计重点：

强调克制、秩序、清晰和品质感。通过细腻的光影、材质、空间关系和微交互表现高级感，而不是依靠复杂装饰、强烈颜色或夸张特效。

## 一、视觉理念

设计应体现「科技存在，但不打扰用户」。

核心原则：

信息结构优先于视觉装饰；使用体验优先于炫技效果；精密感优先于复杂感；柔和空间感优先于强烈视觉冲击。

整体氛围：

安静、智能、可靠、高级、有未来感，同时保持长期使用的舒适性。

避免：

赛博朋克、黑客终端、游戏界面、复杂科幻控制台、强烈未来工业风。

## 二、色彩系统

采用低饱和、高级、柔和的色彩体系。

基础颜色：

珍珠白、暖白色、浅灰色、米色、中性色。

辅助颜色：

柔和蓝、淡紫色、浅绿色、温暖粉色、低饱和强调色。

颜色特点：

低饱和度、低对比度、柔和过渡、自然融合、视觉舒适。

避免：

霓虹色、高饱和蓝紫色、强烈发光色、大面积鲜艳渐变。

## 三、背景设计

使用环境式空间背景。

包含：

大面积柔和径向光晕、模糊环境光、多层空间渐变、轻微色彩扩散、低透明度氛围光。

背景作用：

提供空间深度，增强层次感，使界面具有轻盈漂浮的感觉，同时保持内容清晰。

避免：

复杂纹理、明显网格、强烈背景图案、暗黑科技背景。

## 四、材质设计

采用高级柔和玻璃拟态。

组件表现：

半透明浅色表面、毛玻璃模糊效果、轻微透明边框、内部柔和高光、扩散型阴影、环境光反射。

视觉感觉：

组件像轻盈漂浮在空间中的透明材质层，具有柔和深度，而不是厚重实体。

避免：

厚重阴影、金属质感、真实机械材质、过度透明效果。

## 五、布局设计

采用现代化、空间化的信息布局。

设计原则：

大留白、清晰层级、合理信息密度、模块化结构、视觉平衡。

布局特点：

通过区域划分、层级关系和空间距离表达信息结构，而不是依靠大量边框。

支持：

导航区域、内容区域、信息面板、详情区域、操作区域、状态区域。

避免：

所有内容卡片化、过度装饰布局、只适合展示而不适合操作的页面。

## 六、形态语言

采用柔和几何设计。

特点：

大圆角、平滑边缘、简洁几何结构、统一尺寸体系、轻盈漂浮感。

推荐：

卡片使用较大圆角；按钮使用柔和圆角或胶囊形；输入框保持轻边界和低对比度。

避免：

尖锐边角、复杂装饰形状、过度拟物化设计。

## 七、字体设计

采用现代专业字体体系。

特点：

简洁、清晰、高可读性、专业、具有现代感。

要求：

建立明确标题层级，保持舒适行间距和合理字间距，通过字体大小、粗细和颜色表达信息优先级。

避免：

科幻字体、游戏字体、过度装饰字体。

## 八、图标设计

使用极简线性图标。

特点：

SVG 风格、细线描边、几何结构、统一视觉重量、低饱和颜色。

图标应该：

精确、克制、易识别，与整体空间语言保持一致。

避免：

复杂插画、3D 图标、强装饰性图标。

## 九、精密科技元素

加入精密仪器感，而不是机械工业感。

设计方向：

Precision Instrument Aesthetic。

表现：

系统初始化感、智能状态反馈感、数据处理过程感、设备运行状态感、信息同步过程感。

使用元素：

SVG 描边动画、几何线条、环形轨迹、弧形扫描、状态指示环、点阵结构、进度轨迹、数据流动效果。

图形语言：

圆环、轨道、刻度、微型 HUD、几何结构、精密线框。

视觉特点：

细腻、精准、稳定、克制、高级。

避免：

齿轮、机械零件、工业设备、复杂科幻 HUD、机器人元素。

## 十、动态与动画设计

采用平静自然的动态语言。

动画特点：

缓慢、流畅、精准、自然、有呼吸感。

使用：

淡入淡出、柔和缩放、轻微位移、微视差、描边绘制、环形旋转、状态激活动画、渐进式显示。

加载和状态动画：

使用 SVG line drawing、stroke 描边动画、圆环进度、几何结构生成、状态初始化动画。

表现：

系统启动、智能计算、数据同步、状态变化。

动画节奏：

300ms-1200ms，使用自然缓动曲线。

避免：

快速运动、弹跳效果、强烈闪烁、大量粒子、夸张转场。

## 十一、信息体验设计

保持高级视觉和高效使用之间的平衡。

设计原则：

重要信息优先展示，高频操作保持易访问，复杂内容采用渐进式展示。

要求：

清晰的信息层级、合理的信息密度、明确的状态表达、可预测的操作路径。

避免：

隐藏关键操作、复杂操作流程、为了美观降低效率。

## 十二、组件设计

所有组件保持统一设计语言。

包含：

按钮、卡片、表格、表单、弹窗、抽屉、标签、导航、筛选器、状态提示。

组件统一：

间距、圆角、颜色、字体、阴影、动画方式。

组件特点：

轻量、清晰、柔和、稳定。

## 十三、数据展示设计

数据展示需要兼顾美观和阅读效率。

使用：

简洁表格、轻量数据卡片、状态标签、柔和图表、清晰指标。

要求：

突出关键数据，减少视觉噪音，通过颜色、空间和层级表达状态。

避免：

复杂图表、大量颜色、强网格线、类似传统报表的密集布局。

## 十四、AI 原生交互设计

AI 功能应体现：

智能、可靠、透明、可控。

设计：

AI 建议、生成结果展示、内容预览、编辑能力、状态反馈、用户确认流程。

设计原则：

AI 辅助用户完成任务，用户保持最终控制权。

避免：

黑盒式 AI、不可理解的自动行为、过度 AI 装饰。

## 十五、整体设计目标

最终效果：

形成一种高级智能产品视觉语言。

整体表现：

高级视觉体验 + 清晰信息结构 + 智能交互方式 + 精密科技感 + 平静使用体验。

界面应该：

简洁但不单薄，未来但不夸张，科技但不冰冷，高级但不影响效率。

## 十六、禁止风格

不要生成：

赛博朋克、霓虹科技、黑客终端、游戏 UI、暗黑 HUD、机械工业风、机器人元素、复杂扫描界面、大量发光效果、过度渐变、厚重阴影、复杂背景、廉价 AI 模板感、纯展示型设计。

## 十七、智能体开发行为规范（AI Agent Development Behavior）

生成界面时，不仅关注视觉效果，还需要按照可维护的软件工程方式组织实现。

设计目标：

创建一个可持续扩展的 UI 系统，而不是一次性的页面代码。

***

### 组件化设计原则

采用组件化思维设计界面。

不要将所有页面结构、样式和交互逻辑集中写在单个文件中。

应该：

* 提取可复用 UI 组件
* 建立统一设计规范
* 分离页面逻辑和视觉组件
* 保持组件独立性
* 支持后续扩展和修改

***

### UI 组件库设计

优先创建基础 UI 组件库。

组件包括：

Button、Card、Panel、Modal、Drawer、Input、Select、Table、Tabs、Badge、Tooltip、Loading、Empty State、Navigation、Status Indicator 等。

每个组件应该：

* 拥有独立结构
* 拥有独立样式
* 支持参数配置
* 支持状态变化
* 支持主题扩展

避免：

* 页面内重复创建相同组件
* 复制粘贴 CSS
* 每个页面重新定义样式

***

### 设计 Token 管理

建立统一设计变量。

包括：

颜色：

\--color-primary

\--color-background

\--color-surface

\--color-text

\--color-border

尺寸：

\--radius-small

\--radius-medium

\--radius-large

间距：

\--spacing-xs

\--spacing-sm

\--spacing-md

\--spacing-lg

阴影：

\--shadow-soft

\--shadow-floating

动画：

\--duration-fast

\--duration-normal

\--ease-default

所有组件应该优先使用设计 Token，而不是直接写固定值。

***

### 样式组织规范

避免：

* 一个巨大 CSS 文件
* 页面级重复样式
* 大量临时 class
* 样式相互覆盖

推荐：

按照组件拆分：

components/

&#x20;├── Button

&#x20;├── Card

&#x20;├── Modal

&#x20;├── DataTable

&#x20;└── Loading

styles/

&#x20;├── tokens

&#x20;├── theme

&#x20;└── animations

***

### 页面设计流程

生成页面时按照以下顺序：

1. 分析页面结构和用户任务；
2. 提取通用 UI 模式；
3. 创建基础组件；
4. 定义设计 Token；
5. 组合页面布局；
6. 添加交互状态；
7. 优化响应式表现。

不要直接从 HTML 结构开始堆叠。

***

### 组件复用原则

当多个地方出现相似结构时：

优先抽象为组件。

例如：

多个状态显示：

抽象为 StatusBadge。

多个信息区域：

抽象为 InfoCard。

多个弹窗：

抽象为统一 Dialog。

多个加载状态：

抽象为 Loading 系统。

避免：

为了当前页面快速实现而产生重复代码。

***

### 交互状态完整性

每个组件需要考虑完整状态：

包括：

默认状态、悬停状态、点击状态、加载状态、禁用状态、错误状态、空状态。

状态变化保持：

统一动画、

统一颜色、

统一反馈方式。

***

### 长期维护原则

代码应该：

* 易理解
* 易修改
* 易扩展
* 易复用

优先考虑未来增加：

* 新页面
* 新业务模块
* 新主题
* 新交互方式

避免：

只满足当前页面效果的临时代码。

***

### 智能体工作方式

作为 UI 开发智能体：

先理解设计系统，再生成组件；

先建立基础能力，再组合页面；

先考虑复用，再实现细节。

输出结果应该像一个长期维护的软件产品，而不是单次展示 Demo。
