# aig-ui 设计符合性核验

日期：2026-09-12。检查基线：本地工作树，HEAD 为 `f28b89a`。本次记录设计偏差和修正方向，组件代码保持原样。

## 1. 结论

当前实现**部分符合工程与组件契约，视觉还原尚未达到参考设计要求**。三角绘制、横线错峰、双环旋转、反向擦除、任务状态与组件分层已经存在；实际画面在视觉重量、材质层次、退出交接和跨场景一致性上有明确偏差。

用户后续补充：当前元素缺少示例的科幻感，以及类似《Detroit: Become Human》的风格。该要求已纳入方案 2.0，作为整体视觉目标修正。下文运行时证据保留原核验时间和范围；新增风格方向属于用户需求与执行依据。

用户再次补充（2026-09-12）：已交付的冰蓝信号线装饰方案与 `404.html` 不是同一设计风格，明确以 404.html **加载动画的线绘语言**为唯一基准，并先以 Button 试点。方向、禁止项与 Button 规范见[视觉风格定义](./design-language.md)；本文记录的动效偏差依然有效，实色填充与加重装饰部分按线绘方向一并收束。

### 补充：整体科幻身份不足

结合用户反馈，当前界面在几何层次、仿生状态、精密排版与空间材质上的组合尚未形成鲜明身份。增加模糊或更换强调色只能影响局部，后续需要让图形建立、协同运行、反向解构和加载后工作界面采用一致语言。

新版主方案明确暖白精密科幻方向，以原型为直接还原基准，借鉴游戏的仿生智能气质；原 `design.md` 的“避免游戏 UI”按最新要求细化。网格、缓慢光带、视差与完整材质回到品牌场景的正式范围，精密状态图形在通用组件中按职责复用。具体任务见[方案 2.0](./implementation-plan.md)和 [R0–R6 执行计划](./delivery-plan.md)。

用户强调的重点是 SVG 元素变化、多元素动效配合，以及完成后的反向绘制与解构。本次以[原始 HTML](../reference/404.html)、[原始设计要求](../reference/design.md)和[动效规范](./motion-system.md)为依据，检查实现与运行结果。

## 3. 高优先级偏差

### P1：加载层与新内容重叠，交接出现明显重影

**复现**：打开 LoadingSequence 预览，选择持续等待，待图形完整后触发任务就绪，将有限退出动画定位到相对 450ms。

**实际结果**：三角、加载文字“内容已就绪”和说明仍然清晰，新页面标题、说明与按钮已经出现在相同区域，多个文字层互相覆盖。

**代码原因**：加载层为透明背景，退出动画又在较早阶段维持接近不透明的状态；新内容从退出后 180ms 起同时淡入。缺少清晰的表面遮挡或互补的内容显隐关系。

- [透明加载层](../packages/aig-ui/src/motion/loading-sequence.css)：`.aig-sequence-layer` 第 8–20 行。
- [退出与内容进入](../packages/aig-ui/src/motion/loading-sequence.tsx)：第 138–161 行。

**修正方向**：将“SVG 图形镂空”“加载表面的透明策略”“主内容显现时机”分开处理。品牌页面可以让加载表面随解构退出；透明嵌入场景应控制旧标签与新内容的显隐重叠，保留完整反向擦除且让文字各自可读。共同验收条件是图形撤回清晰、文字无重影、交接无突然闪变。

### P1：主要容器尚未形成统一的柔和玻璃材质

Panel 和 Dialog 主要由实色白底、边框和普通阴影构成；Card 有可选 glass，但其材质规则没有贯通到主要内容容器。访问状态页实际呈现为清晰边框的结果面板，参考页中的渐变表面、内高光、扩散阴影和空间层次明显减弱。

- [Panel](../packages/aig-ui/src/components/panel/panel.css)：第 1–9 行及 Header/Footer 分隔线。
- [Dialog](../packages/aig-ui/src/components/dialog/dialog.css)：第 8–24 行。
- [Card](../packages/aig-ui/src/components/card/card.css)：glass 分支采用单一半透明底色、20px blur 与两层阴影。
- [访问状态配方](../registry/blocks/access-state-page/access-state-page.tsx)：页面直接组合实色 Panel。

**修正方向**：先为品牌展示场景建立一套可复用的表面样张，明确半透明底色、渐变、高光、边界、阴影和环境光的配合，再同步到 Card、Panel、Dialog。表单和数据密集区域可以采用实色内容面，主容器仍需保持同一设计语言。保留用户要求的完整效果，实际可访问性设置单独处理。

## 4. 动效与复用的一致性偏差

### P2：圆环视觉重量明显偏离原型

| 参数 | 原始 HTML | 当前实现 |
| --- | --- | --- |
| 外环线宽 | 0.9 | 1.2 |
| 外环透明度 | 0.30 | 0.65 |
| 内环线宽 | 1.1 | 1.6 |
| 内环透明度 | 0.55 | 0.85 |
| 图形颜色 | `#b98b90` | 品牌标记色与更深的 accent 混合 |
| 1280×720 下的 SVG 大小 | 约 93.6px，由视口高度决定 | 默认 112px |

当前线宽和透明度已由浏览器计算样式核实。结果是双环更抢眼，原始的三角主体与轻淡轨道之间的主次关系发生变化。

证据：[LoadingMark SVG](../packages/aig-ui/src/motion/loading-mark.tsx) 第 106–125 行、[标记颜色](../packages/aig-ui/src/motion/loading-mark.css) 第 1–4 行。

**修正方向**：先以原型值和相同显示尺寸建立基准，再审阅必要变化。功能文字的对比度修正保持在语义文字 Token，装饰圆环沿用独立的品牌视觉参数。

### P2：时间数值保留了，部分缓动与层次改变了

原型的标签和进度轨道使用 `cubic-bezier(0.22,0.61,0.36,1)` 淡入上移。当前 WAAPI 调用省略 easing，浏览器实际报告 `linear`。三角与横线的时长、延迟、双环周期等主要时间 Token 保留，但相同持续时间下的速度变化已经不同。

证据：[LoadingSequence 标签动画](../packages/aig-ui/src/motion/loading-sequence.tsx) 第 103–115 行、[原型 fadeUp 配置](../reference/404.html)。

**修正方向**：把时长、延迟、缓动、运动距离、线宽与透明度一起作为动效基准。只比较 duration 不能判断节奏是否一致。

### P2：预览页的品牌外观没有完整进入组件公共样式

演示 CSS 额外改变标题字距和字重、说明字号与字距，并单独为 SVG 添加 drop-shadow。这些选择器依赖 `.aig-sequence-demo-stage`，普通消费项目仅导入公共 motion 样式时不会获得同样效果。

证据：[演示专用样式](../packages/aig-ui/src/motion/loading-sequence.demo.css) 第 17–28 行、[公共加载样式](../packages/aig-ui/src/motion/loading-sequence.css)。

**修正方向**：将确认过的品牌外观放入组件默认样式或明确的可复用配方；演示层负责布局和调试工具。用直接导入发布包的独立页面对照，证明“预览可见的设计”与“接入可得到的设计”一致。

### P2：慢速预览没有统一控制全部轨道

**复现**：选择 0.25 倍、持续等待，再点击重试，读取各动画的 playbackRate。

| 动画 | 本次实际 playbackRate |
| --- | ---: |
| 外环、内环、进度扫光 | 0.25 |
| 三角、横线 | 1 |
| 标签、进度轨道淡入 | 1 |

演示通过 effect 与 MutationObserver 扫描当时存在的动画，后续创建的 WAAPI 实例可能错过倍率设置。自动 ready 仍由独立的真实时间 setTimeout 驱动，也没有与慢速和暂停共用演示时钟。原版在 iframe 中显示，现有 host 控制没有覆盖该 iframe 的动画。

证据：[演示控制](../packages/aig-ui/src/motion/loading-sequence.stories.tsx) 第 22–45 行及原版 iframe 分支。

**修正方向**：演示样张使用统一的受控时间或动画注册集合，倍率、暂停和任务就绪一起推进；原版与当前版本采用相同条件。另保留正常真实时间的生命周期检查。修好控制之前，慢速回放不能作为设计验收依据。

## 5. 预览与验收方式的影响

预览页将每个组件放入实色白底、带边框和阴影的统一盒子。玻璃 Card 位于这样的平坦背景上，背后几乎没有可区分的内容或环境层，难以体现玻璃材质的实际作用。这个容器适合检查孤立状态，还需补充品牌场景和真实操作页面。

现有 [motion.spec.ts](../tests/browser/motion.spec.ts) 主要验证描边进度、fill 为 none、回调次数、生命周期和截图保存。其中第 82 行固定要求加载层背景透明，第 106 行要求早期退出 opacity 大于 0.9，但没有验证加载文字与新内容是否重叠。截图保存本身也没有和经确认的参考图比较。

因此，旧的行为检查通过与本次发现的视觉偏差可以同时存在。当前 `progress.md` 已将用户视觉审阅列为待完成事项，该状态应保留。

## 6. 根因与修正顺序

工程已经建立了组件数量、API 和分发链；设计仍缺少一套实际确认、能够复用到各组件的视觉基准。前一版实施方案也把实色默认、较小圆角和简化材质提前写入候选值，这部分工程取舍需要重新对照用户认可的参考图，而不能直接当成已经确认的视觉决定。

以下为核验时确定的核心修正顺序，完整执行已由方案 2.0 的 R0–R6 展开；退出时间点以新版动效规范为准。每一步形成可审阅结果：

1. **修正原版与当前版本的对照工具。** 同尺寸、同进度、同任务时钟，覆盖正常播放和慢速回放。
2. **校准 LoadingMark。** 保留原始几何、描边重量、透明度、颜色与错峰节奏。
3. **修正 LoadingSequence 交接。** 重点检查退出 0/180/450/720/980/1330ms，验证反向绘制完整且文字无重影；Inline 与 Fullscreen 分别确认。
4. **建立 Card/Panel/Dialog 的共享材质样张。** 加载后交接到这套真实内容表面，确认整体空间感。
5. **同步公共样式与独立消费页面。** 演示与实际导入使用同一视觉实现，再扩展到其他组件。

已有的任务隔离、类型、可访问性和分发工程可以继续使用。修正工作的重点是已有核心的视觉参数、表面层次和编排关系。

## 7. 下一轮视觉完成条件

- 原始参考与实现同尺寸对照，图形主体与双环层次保持一致。
- 三角、横线、文字、进度的错峰和缓动符合确认样张。
- 反向擦除保持可见，解构与内容交接清晰，无文字重影和突然闪变。
- 暂停、慢速与就绪信号能准确重现同一时间轴。
- 主要容器体现确认过的柔和材质，实际内容保持清楚可读。
- 公共组件、页面配方和独立安装包的视觉一致。
- 用户确认基准后再加入截图比较与关键时序检查，避免测试固定未经确认的视觉取舍。

**最高影响的两项是退出交接的重影与共享材质的缺失。** 先完成这两项，再推广到已有组件，比继续增加组件数量更能接近本次设计目标。
