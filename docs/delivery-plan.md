# aig-ui 实施排期与验收

版本：方案 2.0，修订日期：2026-09-12。本计划落实[实施方案](./implementation-plan.md)、[加载动效规范](./motion-system.md)和[AI 复用规范](./ai-reuse-spec.md)。当前已有本地 Alpha，下一轮执行 R0–R6 的视觉修正；旧版 S0–S5 新建项目排期由本计划替代。历史交付与本轮状态见[实施进度](./progress.md)。

## 1. 范围与资源假设

现有范围为 M0 动效 2 个、G0 基础 17 个、G1 通用 23 个、A1 AI 交互 8 个，共 50 个组件族，以及 5 个页面组合。本轮复用已有工程与交互，修正科幻视觉、完整动效、共享材质、公共样式和消费一致性。正式发布还需完成真实业务、辅助技术及公共安装验证。

修正工作初估 27–40 工程人日，约 20% 缓冲后为 33–48 人日。两名前端配合约半职设计和半职测试，初估 4–6 个工作周；一名前端约 7–10 周。R0 完成后按实际修改量重新估算，用户样张反馈、真实试点与外部发布准备单独计时。

维护者负责依赖、API、版本和提交；实施者负责真实调用链、组件和可运行样张；视觉负责人按参考和用户反馈校准图形、材质、节奏；验证负责人检查浏览器、可访问性与消费结果。同一人可兼任，实际资源决定日历进度。

### 2.1 R0：建立可靠的对照

主要文件：`packages/aig-ui/src/motion/loading-sequence.stories.tsx`、`loading-sequence.demo.css`、`apps/preview/src/main.tsx`、`apps/preview/src/preview.css`、`tests/browser/motion.spec.ts`。

1. 记录 HEAD、工作树、Node/pnpm、浏览器、DPR、字体和视口，保存原参考、当前 Alpha 的完整播放与缺陷帧。
2. 校准参考 iframe 与当前组件的可用空间、SVG 尺寸和背景；固定 1280×720 对照，辅助检查 1920×1080。
3. 统一演示时钟，覆盖延迟创建的 CSS/WAAPI 动画、自动 ready、暂停和重放。原型适配层控制其定时退出和 DOM 移除，原始 HTML 保持独立可播放。
4. 加入 0.25/0.5/1 倍率检查及退出 450ms 重影复现。真实时钟检查单独保留。
5. 预览区同时展示孤立状态与品牌场景，让材料面对真实环境背景；演示框架只负责布局和工具。

完成证据：同时间点连续帧、每条轨道的倍率记录、暂停前后时间和 ready 不变的检查、重放一致性。存图行为与视觉比较分开记录。

### 2.2 R1：恢复图形与建立节奏

主要文件：`motion/loading-mark.tsx`、`loading-mark.css`、`loading-sequence.tsx`、`loading-sequence.css`、`tokens/source.json`、`scripts/tokens.mjs` 及就近说明。

1. 恢复外环 0.9/0.30、内环 1.1/0.55、三角和横线 2.2、原型几何与 `#b98b90`；相同显示尺寸下比较。
2. 还原三角、横线、标签、进度轨道和扫光的完整延迟、时长及各自缓动，双环保留 14s/7s 反向运行。
3. 让身份标签、说明与图形形成精密层次，中文业务说明保持可读；确认的光晕与文字样式由公共组件或配方提供。
4. 沿用 SVG、CSS、WAAPI 和现有 Token 生成链；主题色、装饰色与功能文字色分离。

完成证据：入场关键帧、完整等待画面、64/96/128px 及原型自适应尺寸对照、公共导入页与 Story 外观一致。对现有通过的状态接口作必要回归。

### 2.3 R2：恢复反向构建与清晰交接

主要文件：`motion/loading-sequence.tsx`、`loading-sequence.css`、`loading-mark.tsx`、`tokens/source.json`、`tests/browser/motion.spec.ts`。

1. 将旧标签、SVG 标记、加载表面、主内容分开控制。先按动效规范的 0/180/720/980/1520/2130ms 候选建立可运行退出样张。
2. Inline 保留镂空与透明留白，旧文字退出后再显现主内容；Fullscreen 的背景表面参与消散，Portal 与焦点职责保持完整。
3. 从当前有效描边进度撤回，有限动画通过实际完成信号汇合；提前完成时按实际已出现内容缩短轨道。
4. 覆盖 ready、错误、重试、新 taskId、卸载、Strict Mode、重复 ready 和系统减少动画中途改变。
5. 替换仅固定透明背景或单个 opacity 数值的视觉判断，保留其原本要保护的镂空、可见撤回和清晰交接要求。

完成证据：正常退出与提前退出连续帧，450ms 无重影，最后一段撤回仍可感知，Fullscreen 无突变遮挡，每次 onExited 与动画清理结果。新总时长确认后同步 Token、说明及检查时间点。

### 2.4 R3：建立科幻品牌场景与共享材料

主要文件：`tokens/source.json`、`scripts/tokens.mjs`、`components/card/`、`panel/`、`dialog/`、`button/`、`registry/blocks/access-state-page/`、相关预览与样式出口。

1. 以原型环境径向光、44px 极淡网格、12s 光带、46px 玻璃与完整高光/阴影建立品牌主表面。
2. Card 沿用 `material="glass | solid"`，修正版默认改为 glass；Panel 根部和 Dialog.Content 增加同名选项并默认 glass，内部阅读面独立。同步 Props、样式、说明、调用方和默认值迁移记录，直接导入组件也获得品牌材料。
3. 用暖白与暖玫瑰建立必需样张；局部冰蓝只作为对照候选，按反馈决定是否纳入正式 Token。
4. 用几何主体、细弧、短状态线、等宽编号和清楚的标题层级强化科幻气质，界面文案继续表达真实任务。
5. 加载完成后接续三个真实访问状态，再放入可操作表单和详情弹窗，证明视觉延续到工作界面。

完成证据：品牌页面、Card/Panel/Dialog 同环境样张、Button 各层级与焦点状态、真实文字对比度、内容滚动、用户视觉确认记录。组件公共样式与演示使用同一份材料规则。

## 3. 验收记录与质量门槛

### 3.1 视觉记录

每条记录包含：组件或页面、方案版本、源码提交、视口与 DPR、浏览器与字体、状态、时间点、参考图/实际图、判断、遗留项、复核人或用户反馈。实际生成记录与图片可放入本地 `artifacts/design-review/`；确认基准应保存在版本控制的测试快照或项目已有资产目录，避免随临时产物清理。

| 检查项 | 完成条件 |
| --- | --- |
| 科幻身份 | 原型几何、精密层级和仿生运行感可识别，加载后工作页面延续该风格 |
| 图形层级 | 主轮廓、内弧、外轨的重量与相同尺寸参考一致 |
| 材质空间 | 渐变表面、高光、扩散阴影和环境层共同可见，正文清楚 |
| 动态叙事 | 建立、协同、撤回、消散和内容进入各自可感知，文字交接清楚 |
| 复用一致性 | 样张、公共包与 Registry 组合的外观来源一致 |
| 可操作性 | 键盘、输入、滚动、焦点、长文本与恢复操作保持可用 |

视觉确认与行为测试分别通过后才记为该切片完成。像素比较在固定环境下对照确认基准，容差按字体抗锯齿等真实差异设置；本轮已知重影、轨道失真和材质丢失属于必须处理的偏差。

### 3.2 动效与交互

动效检查使用规范中的新时间点，另保留旧缺陷的 450ms 和 1330ms。ready 取 0/200/1000/2400/10000ms，覆盖重复 ready、新任务替换、双实例、取消、卸载和减少动画。有限动画完成、无限动画清理和 onExited 分别检查。

通用回归覆盖：复制成功/失败、表单值与错误、中文输入法、浮层焦点/关闭/主题、选择检索、表格滚动和分页、消息阅读位置、产物 revision 冲突。静态低风险样式通过代表性实际渲染核验，状态和生命周期保留能捕获回归的最小检查。

### 3.3 视口与可访问性

覆盖 360×800、390×844、768×1024、1280×720、1440×900、1920×1080，另验收 667×375、200% 缩放、320 CSS px 重排和长中英文。数据表、代码等二维内容在独立区域滚动，关键动作始终可达。

自动 axe 与人工键盘相互补充。正式支持还需真实 Safari/iOS、Windows NVDA + Edge/Firefox、VoiceOver + Safari。forced-colors、显式实色和 reduced-motion 分开记录；正常环境保留完整科幻动效与材料。普通文字 4.5:1、大字及适用非文本信息 3:1 作为既有验收基线，适用规则见 [WCAG 2.2](https://www.w3.org/WAI/WCAG22/quickref/)。

## 4. 性能与效果完整性

记录设备、系统、浏览器、生产构建、尺寸、数据量和次数。保留完整视觉，通过减少重复渲染、布局失效、无用合成层与遗留句柄优化；设备性能不触发删减动画。模糊 API 不可用和用户辅助偏好使用独立兼容表现。

| 对象 | 检查目标 |
| --- | --- |
| 加载清理 | 退出/卸载后本实例活跃动画、计时器与 RAF 为 0 |
| 完整序列 | 60Hz 基准设备 p95 帧间隔候选 ≤20ms；记录可归因的 >50ms 长任务，1280×720 和 1920×1080 各至少 5 次 |
| 包与样式 | 对同一入口、同一构建比较修改前后 gzip；解释增长来源 |
| 列表 | 100 行×8 列，排序/切页 p95 候选 <100ms，排除网络 |
| AI 阅读 | 100 条历史消息、20KB 当前文本、20 次/秒更新下可操作，阅读位置稳定 |

旧方案 LoadingSequence ≤15KB 与进度中的完整 motion 入口约 25.9KiB 属于不同测量对象，R6 分别测量后制定预算。性能目标是待验证的工程指标，视觉等效和使用正确性共同决定优化是否采用。

## 5. 当前可用命令与执行依赖

以下命令已在根 package.json 中存在，具体能力以脚本实现为准。本次文档修订只做静态核对；后续代码切片运行相关检查。

| 命令 | 当前职责 |
| --- | --- |
| `pnpm preview` / `pnpm dev` | 统一预览 / Storybook |
| `pnpm tokens` | 从 source.json 生成 Token |
| `pnpm lint` / `pnpm typecheck` | ESLint / Token 生成与 TypeScript 语义检查 |
| `pnpm test` | Vitest 逻辑与交互检查 |
| `pnpm build` | Token、包编译、样式/资料与 Registry 生成 |
| `pnpm check` | 顺序运行 lint、typecheck、test、build |
| `pnpm build:preview` / `pnpm build:docs` | 统一预览 / Storybook 生产构建 |
| `pnpm check:artifacts` | 重建并校验机器资料和 Registry；其他出口检查由消费流程补充 |
| `pnpm pack:local` / `pnpm prepare:consumer` | 生成 tarball / 准备 Registry 消费源码 |
| `pnpm test:motion` / `pnpm test:browser` | 当前 Playwright 配置下的动效 / 全部浏览器场景 |
| `pnpm check:size` | 独立消费构建的体积记录 |

R0–R2 修改共享 Token 或动画时运行适用类型、交互、动效和实际播放检查；R3–R5 按真实调用方扩大回归；R6 运行完整消费与交付链。当前 Playwright 配置会启动 Vite 与 Next 消费服务，即使只跑 motion 也要先准备 tarball、安装消费依赖并完成 Next 构建，或在 R0 明确拆分配置后更新本节。

```sh
pnpm check
pnpm build:docs
pnpm build:preview
pnpm pack:local
pnpm prepare:consumer
pnpm --dir examples/vite-consumer install --ignore-workspace --no-frozen-lockfile
pnpm --dir examples/next-consumer install --ignore-workspace --no-frozen-lockfile
pnpm --dir examples/vite-consumer build
pnpm --dir examples/next-consumer build
pnpm exec playwright install chromium
pnpm test:browser
pnpm check:size
```

消费依赖的 tarball 路径随实际包版本同步。上述流程复用根 README 的现有入口，`test:a11y`、`check:consumers`、`check:ai` 当前没有独立命令；对应职责通过已有浏览器、消费与资料流程完成，并补充必要的人工/AI 记录。首次执行前检查所需端口与已有服务，只清理本次创建的进程。

## 6. 提交、资料同步与回退

每个组件或职责一致的组件族完成适用验证后独立提交，只暂存本轮文件。公共 Token、动效基础、对照工具分别形成可审阅切片。提交标题采用简体中文 Conventional Commits，沿用已恢复的签名配置；包含 AI 生成代码时按仓库约定添加 Co-authored-by。

每次完成同步进度、就近 README/Story、类型和受影响的机器资料；公共视觉值变化写清前后样张与范围。新代码的公共说明和关键注释使用简体中文。生成资料由源码和构建脚本更新。

本轮修正采用向前可追踪的提交链。出现回归时回退对应切片或发布修复，保留用户原有修改；共享 Token 回退同时回归依赖组件。已有 Registry 安装源码通过新旧 diff 合并，消费项目保持可锁定的旧版本。

## 8. 首批可直接执行的顺序

5. 将视觉确认结果回写 Token 和规范，按 R4–R6 逐组迁移并交付。

## 9. 高影响风险与机会

**风格解释和可复现的视觉基准**决定本轮方向是否准确，《Detroit: Become Human》的具体画面仍有选择空间；先用用户认可的 HTML 建立可审阅样张。**共享材料与公共样式同源**能同时修正大量组件，而**仅验证状态数值**仍可能遗漏重影、轨道配合和空间感，必须结合完整播放与确认样张。
