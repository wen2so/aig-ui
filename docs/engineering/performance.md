# 性能测量与预算

测量日期：2026-09-17。以下结果来自本地 Windows、Node 24.9.0 和 Playwright Chromium。构建体积与运行时耗时分别记录。

## 预览加载

目录只包含名称、中文标签、说明、分类和加载器。详情按组件加载 Story、README、示例源码、扩展示例和 API；Markdown 渲染器单独加载。共享演示辅助逻辑及页面组合仍由共享模块提供。

| 指标       | 审核报告基线 |  本次构建 |
| ---------- | -----------: | --------: |
| 主 JS      |  1,127.38 kB | 317.41 kB |
| 主 JS gzip |    296.63 kB |  98.95 kB |

主 JS 不等于全部初次请求。本次按 manifest 累加入口及其静态 JS 依赖为 **408,330 bytes，gzip 合计 135,079 bytes**，预算按这个口径检查。该统计不含 CSS、字体和详情动态块，也不代表组件库按需消费体积。API reader 排除 Story、测试和应用入口，同一构建周期复用；没有跨构建的磁盘缓存。多次本地构建的 API load 约为 2.8～3.5 秒，审核报告为约 5.2 秒，环境与缓存会影响耗时。

## 2026-09-18 控件扩充测量

新增 21 项控件后，组件元数据为 71 项、预览入口为 78 项。安装本轮 tarball 测量：基础样式从 84,162 增至 **97,897 bytes**，gzip 从 17,491 增至 **19,733 bytes**；增长来自新增控件样式、统一交互表面和密度规则。本轮仅更新 styles.css 的基线，增长容差仍为 10%，其余入口预算保持不变。

当前预览入口及静态 JS 依赖合计 **420,109 bytes，gzip 137,909 bytes**，仍在原预算内；目录未提前加载全部示例。Button 独立入口 **19,263 bytes，gzip 6,273 bytes**，未引入 AI Markdown 依赖。组件数量增加不等于运行时变慢，本轮没有重新测量密集按钮挂载耗时，下节保留 2026-09-17 样本。

## 密集按钮

入口：`http://127.0.0.1:5173/button-performance.html?count=200`。组件为 `entrance={false}`，观察静止状态、首次 hover 和 30 次逐帧滚动。执行 `pnpm exec playwright test -c playwright.motion.config.ts button-performance --workers=1`，报告写入 `artifacts/performance/`。

| 按钮数量 | 优化前矩形节点 | 优化后未交互矩形节点 | 优化前后代节点样本 | 优化后后代节点样本 |
| -------- | -------------: | -------------------: | -----------------: | -----------------: |
| 50       |          5,200 |                    0 |              8,318 |              2,786 |
| 200      |         20,800 |                    0 |             33,354 |             11,330 |

上述前后各取一次独立运行，刻面随机组合会使后代总数略有变化。相同两次运行中，50 个按钮的挂载记录为 270.4 / 85.3 ms，200 个为 614.3 / 269.1 ms；首次交互分别为 105.5 / 56.2 ms、72.4 / 66.7 ms。30 次逐帧滚动分别为 693.6 / 496.7 ms、680.8 / 534.0 ms。这些耗时包含机器负载、开发服务和缓存差异，不能作为稳定提速比例或帧率瓶颈结论。

优化只延迟创建边缘轨迹与浅色副本，并复用文档级模板。首次交互后保留节点以复用停止位置，离开后三秒收回。刻面、内容遮罩和对应观察器仍按实例维护。现有三角/四边形、渐隐尾迹、三等分间距、遮罩与中间帧接缝检查继续执行；后续是否共享尺寸观察器，应依据实际页面的持续性能采样决定。

## 检查门槛

`pnpm check:size` 从独立安装的 tarball 测量 button、motion、ai 与三组样式，同时检查 Button 入口的 Markdown 依赖隔离。预览要求已有 `pnpm build:preview` 的 manifest。基线位于 `scripts/size-budgets.json`，原始与 gzip 任一指标超出基线 10% 时失败，报告保留具体超限项。

已通过人为降低 Button gzip 基线验证失败路径，并恢复基线后再次通过正常检查。合理增长需要明确执行 `node scripts/size.mjs --update-baseline`，审阅差异后提交；CI 禁止更新基线。
